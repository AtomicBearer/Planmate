# Module ownership

Keep vanilla components and shared rules. New browser modules must be linked from their page, listed in `public-files.js` and added to the dependency checks when they need another script. Private server modules remain outside the public allowlist.

| Area                  | Files                                                                                                    | Responsibility                                                                                                    |
| --------------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Theme                 | `shared.css`, `personality.css`, `motion.js`, `assets/`                                                  | Shared palette/typography, scrapbook artwork, finite reduced-motion-aware effects                                 |
| Entry and profile     | `login.html/css/js`, `profile.html/css/js`, `profile-rules.js`, `profile-store.js`                       | Explicit demo versus sign-in, safe private profile fields, wishlist, planning return context                      |
| Accounts              | `account-client.js`, private `account-service.js`                                                        | Server configuration, verified Google credentials, cookie sessions/CSRF, sign-out and profile API access          |
| Dashboard composition | `dashboard.html`, `dashboard.js`, `dashboard.css`, `dashboard-responsive.css`                            | Application state, shared/local mutation adapters, discovery and page composition; responsive rules are separate  |
| Navigation            | `dashboard-navigation.js`                                                                                | Section names, accessible selection, trip/day/page URL context                                                    |
| Shared refresh        | `shared-sync.js`                                                                                         | Bounded polling, focus refresh, context checks, dropping delayed old revisions                                    |
| Private drafts        | `form-drafts.js`                                                                                         | Dirty values, scoped storage, recovery, source review and focus/cursor/discussion preservation                    |
| Common UI             | `planner-ui.js`, `browser-utils.js`                                                                      | Escaping, guarded storage, common fields/panels/dialogs, reusing loaded image nodes                               |
| Rendering             | `dashboard-renderers.js`, `place-illustrations.js`                                                       | Idea/itinerary/preview templates and original category artwork; no shared mutations                               |
| Agreement and fit     | `planning-time.js`, `planning-rules.js`, `group-fit.js`, `group-planning.js`, `group-planning.css`       | Polling, attendance, explicit confirmation, member permissions, personal trip needs, deterministic scoring/drafts |
| Outing                | `outing-rules.js`, `outing-ui.js`, private `map-service.js`                                              | Today/timezone, visits, comments, reorder/undo, linked map and optional route adapter                             |
| Expenses and memories | `expense-rules.js`, `memories-ui.js`, private `media-store.js`                                           | Integer-paise accounting, separate repayments, private uploads/captions and Sharp image processing                |
| Planner and catalogue | `planner-core.js`, `catalogue.js`                                                                        | Shared scheduling/validation/migrations, starter references, overlap/travel rules                                 |
| PDF                   | `itinerary-export.js`, `assets/vendor/`, `assets/pdf-fonts.js`, `licenses/pdf-export/`                   | Themed snapshot export, local libraries/fonts and license notices                                                 |
| Persistence and APIs  | private `server.js`, `plan-store.js`, `discovery.js`, `public-files.js`                                  | Shared API authorization, SQLite transactions/import, transient provider data and explicit static serving         |
| Maintenance           | `scripts/check-project.js`, `scripts/backup.js`, `scripts/pilot-goa.js`, `scripts/prepare-pdf-assets.js` | Script/link/syntax checks, offline recovery, bounded Goa pilot and PDF asset rebuild                              |
| Verification          | `tests/*.test.js`, `tests/browser/*.cjs`, `.github/workflows/check.yml`                                  | Shared rule/server regressions, portable disposable browser cases and prepared CI                                 |

Load `browser-utils.js` before UI consumers. Load `account-client.js` before profile/dashboard entry logic; page initialization waits for its session lookup. `profile-rules.js` precedes `profile-store.js`. Shared rule order is planning time → group fit → outing/expense → agreement → planner core. Common UI, renderers, navigation and synchronization load before `dashboard.js`; feature interfaces load after the rule modules. Motion runs last. Styles load shared tokens → dashboard base/responsive → page/group styles → scrapbook personality.

The server supplies revisions and permissions. UI modules submit through the dashboard adapter; draft storage never submits data. SQLite compares the current trip revision inside a transaction; provider media is never put into the trip-photo store. Account profiles have a separate revision and do not share preferences with a trip automatically.
