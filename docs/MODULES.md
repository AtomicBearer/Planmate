# Module ownership

Keep vanilla components and shared rules. New browser modules must be linked from their page, listed in `server/public-files.js` and added to the dependency checks when they need another script. Private server modules remain outside the public allowlist.

Load `public/js/browser-utils.js` before UI consumers. Load `public/js/account-client.js` before profile/dashboard entry logic; page initialization waits for its session lookup. `shared/profile-rules.js` precedes `public/js/profile-store.js`. Shared rule order is planning time → group fit → outing/expense → agreement → planner core. Common UI, renderers, navigation and synchronization load before `public/js/dashboard.js`; feature interfaces load after the rule modules. Motion runs last. Styles load shared tokens → dashboard base/responsive → page/group styles → scrapbook personality.

The server supplies revisions and permissions. UI modules submit through the dashboard adapter; draft storage never submits data. SQLite compares the current trip revision inside a transaction; provider media is never put into the trip-photo store. Account profiles have a separate revision and do not share preferences with a trip automatically.

The presentation guide uses `public/demo.html`, `public/css/demo.css`, `public/js/demo.js` and private `server/services/integrations.js`. It reads configuration-only `/api/integrations/status` and never calls paid services. `scripts/check-launch.js` checks public deployment settings; `scripts/pilot-goa.js` performs optional bounded live discovery. Both package commands load `.env` when present. `server/static-files.js` maps the public allowlist to organized files and retains old public asset URL aliases. Shared rules are intentionally public at `/shared/`; `server/` and `docs/` remain private.
